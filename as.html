Description

I built this little prototype to get to know better how this framework works.

It helped me understand a little more how some engines work on the inside. I always worked in engines such as Unity, Godot or GameMaker where the assets are loaded by the engine automatically and i completely forgot that the assets have to be loaded in some point of the game loop.

I'm glad i decided to try Monogame, it opened my eyes to more aspects of videogames development i used to take for granted and now i know there is a lot more than just draging and droping to make a game.

Engeneering and technical breakdown

The challenge:
Create a tiny game to understand how the game loop really works outside conventional game engines.

The solution:
I created a short game focusing on the 3 main parts of the game loop:

1. Boot
The binary excecutes and the content is loaded before entering the main loop.

2. Loading content
This is what got me the most. I made the decision of not building a dedicated content manager class as this games uses just a couple sprites.
But for me it should be mandatory to build one for complete projects where lots of assets are required.

3. The actual loop
I defined the main logic to make the game work: the player, the bullets, the enemies and the game over message.
